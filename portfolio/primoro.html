A bit of context

Primoro is a multi-product operating system for modern dental practices — designed to replace the patchwork of legacy tools clinical and admin teams stitch together. Think appointment manager, staff communication hub, consent templates, tasks, and Primoro Pay, all in one platform.

I'm leading design across the system on a freelance/consultant retainer, partnering closely with the founder team to ship modules end-to-end — from research through high-fidelity prototypes and engineering handoff. The work spans multiple user roles (clinical, admin, front-desk) and surfaces (desktop web, tablet for chairside), with RBAC and operational workflows baked into nearly every screen.

When it ships

Here's what the case study will likely cover.

Module 01

Staff Portal & Communication Hub

Designing for cross-role coordination — clinical, admin, and front-desk staff working from the same shared workspace without stepping on each other.

Module 02

Appointment Manager

Spec v2.1 → v2.2 — accessibility flows, arrival states, tablet boundaries, waitlist logic, deposit timing, and AI calendar suggestions.

Module 03

Tasks Manager

List, Calendar, and Timeline views, filter panels, work packages, and tablet-optimized Surgery Checklist screens.

Module 04

Primoro Pay

Payment flow mapping across FOH dashboard, patient list, and Pay module — invoices, refunds, ledger, and reconciliation.

Module 05

Consent Template Library

Digitizing legacy paper-based consent forms into a configurable template library with version control and audit trails.

System

Design System & RBAC Patterns

Building the Primoro design system in Figma — typography, color, components — and establishing role-based UI patterns across the platform.
